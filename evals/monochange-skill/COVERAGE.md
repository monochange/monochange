# Coverage: monochange skill evaluation matrix

The committed scenario inventory contains 63 scenarios: 38 agent tasks and 25 deterministic contracts, with 324 checks across 24 fixture families. There are 23 primary scenario fixtures; the Go tag contract also copies the supplemental `planning-go-tag-baselines` family for custom-format and prerelease-suffix checks. This file describes authored coverage; passing execution results and skill comparisons belong in [FINDINGS.md](FINDINGS.md).

## What the matrix exercises

- Adoption and updates: mixed ecosystems, independent releases, private workspace roots, explicit registrations versus raw discovery, automatic ownership filters, existing configuration, custom workflows, and source-provider setup.
- Ecosystem decisions: Cargo dependencies, scoped npm ids, Deno JSON and JSONC, Dart workspace roots, the Flutter alias, PEP 621 and Poetry version fields, Go tagged and first-release baselines, and colliding manifest names.
- Release planning: propagation modes, pre-1.0 shifts, explicit stable versions, group baselines, prerelease preview stability and fixed-base preparation, typed dependency prefixes, structured and regex version stamps, custom command input forwarding, changelog filtering, titles, and audience outputs.
- Guardrails: invalid config and target recovery, initialization refusal, skill installation/update errors and symlink boundaries, fixed skill-topic inventory, release-state tracking, readiness gates, and preparation without publication.
- Deterministic CLI contracts: format/filter behavior, changeset dry runs, cross-stream detection, quoted pnpm lockfile rewriting and command replacement, custom Go tag baselines and prerelease suffix parsing, lifecycle records, release-note selection, generated subagent guidance, and a Solana/Pina release shape (lockstep program-plus-SDK group, stream-derived on-chain deploy eligibility, SBF digest identity, pina deploy command workflow, and the durable record read back from the tag).

Agent tasks evaluate decisions and resulting artifacts. Contracts run without a model and pin mechanical CLI behavior; running them under several variant labels does not compare the skills. The full inventory below is derived from the scenario JSON files. A scenario's checks define its precise boundary, so read them before extending an existing case.

## Remaining limits and useful next coverage

- Registry uploads, real hosted-provider mutations, tags pushed to remotes, release PR merges, and release/publish workflows are excluded. Readiness and lifecycle tests establish local gates, not production publication success.
- The suite does not exhaust every CLI command, configuration combination, ecosystem adapter, or operating system. Named gaps include GitHub Actions package ownership/floating-tag behavior, date/datetime prerelease numbering and full stable promotion, and lockfile formats beyond the focused quoted-pnpm contract. Rust unit and integration suites cover additional implementation behavior separately.
- Fixtures are small synthetic repositories. Long histories, production-scale graphs, unavailable package managers, authentication outages, and performance constraints need separate testing.
- Semantic severity can depend on toolchains and dependencies. The breaking-change task grades human release intent; the suite does not prove complete analyzer coverage across languages or configurations.
- Skill variants can only be compared through completed agent runs that consulted the intended guidance. Installed variants use distinct trees; CLI-discovered guidance comes from one binary and cannot distinguish those installed variants.
- A single run per scenario/model/variant is regression evidence, not a reliable ranking. Repeat divergent cells, record requested/effective models and provenance, and distinguish runtime or grader failures from agent outcomes. Infrastructure tests make grading more trustworthy but do not prove the checks themselves capture every requirement.

Run `devenv shell eval:skill --list` to inspect the current set, `devenv shell eval:skill:contract` for model-free contracts, and select explicit scenarios/variants for paid runs. Keep coverage claims synchronized when the inventory changes.
