# Upgrading to 0.23

Workspaces that publish Dart or Flutter packages to pub.dev with trusted publishing now publish each package from its own release tag. Workspaces without trusted pub.dev packages need no changes.

## CLI: pub.dev packages publish from their own tag

pub.dev only accepts a trusted upload from a GitHub Actions run that a `push` or `workflow_dispatch` event started on exactly `refs/tags/<package tag>`. `monochange publish packages` now applies that rule before uploading a pub.dev package that publishes with trusted publishing and no `PUB_TOKEN`:

- When the run does not match, the package is not uploaded and gets the status `deferred_to_tag`. Earlier versions attempted the upload, pub.dev rejected it, and the packages after it were skipped.
- On a pub.dev package's own tag, only the trusted pub.dev packages released under that tag publish; the rest get `skipped_out_of_scope`, and each message names the run that publishes the package. The release's primary tag is exempt: a run on it publishes every other package as before.

Runs on branches, on the primary tag, and on unrelated tags publish exactly what they published before, except that trusted pub.dev packages wait for their own tag. A workspace without trusted pub.dev packages publishes exactly as before on every ref.

Publish from tags: run the publish workflow on the release's primary tag, then dispatch it once for each deferred tag. On each package's pub.dev admin page, set the tag pattern to the package's release tag with `{{version}}` and enable publishing from `workflow_dispatch` events. [CI, package publishing, and release PR flows](../13-ci-and-publishing.md#github--dart--flutter-pubdev-trusted-publishing) has a workflow that dispatches the deferred tags.

Scripts that read `monochange publish packages --format json` or a publish result artifact must accept the new status values and fields:

```json
{
	"status": "deferred_to_tag",
	"deferred_to": {
		"reason": "wrong_ref",
		"tag": "my_package/v0.2.1",
		"ref": "refs/tags/my_package/v0.2.1",
		"command": "gh workflow run publish.yml --repo owner/repo --ref my_package/v0.2.1"
	}
}
```

`deferred_to.reason` is `wrong_ref`, `wrong_ref_type`, `wrong_event`, or `unknown_ref`. `summary.deferred` counts `deferred_to_tag` packages and `summary.out_of_scope` counts `skipped_out_of_scope` packages; both are omitted when zero. Neither status fails the run, and `--resume` plans both again instead of treating them as complete.

## Configuration: trusted pub.dev packages need a release tag

`monochange step validate` and `monochange publish readiness` now report an error for a pub.dev package that publishes with trusted publishing but whose releases create no tag. Set `tag = true` on the package, or on its group when the package belongs to one:

```toml
# before
[package.my_package]
path = "packages/my_package"
type = "dart"

# after
[package.my_package]
path = "packages/my_package"
type = "dart"
tag = true
```

To keep publishing without a tag, publish with a pub.dev token instead (`publish = { trusted_publishing = false }` and a `PUB_TOKEN` in the publish job), or hand the upload to another workflow with `publish = { mode = "external" }`.

## Rust: `monochange_publish`

Rust callers that build these types with every field, or match `PackagePublishStatus` exhaustively, must handle the new items:

```rust
use monochange_publish::PackagePublishStatus;
use monochange_publish::PublishReleaseTag;
use monochange_publish::PublishRunScope;

// `PublishRequest` gained `release_tag`, where `None` means the package's
// releases create no tag, and `run_scope`, which the executor reads in
// release mode. `PublishRunScope::Publish` keeps the earlier behaviour.
let release_tag = Some(PublishReleaseTag {
    name: "my_package/v0.2.1".to_string(),
});
let run_scope = PublishRunScope::Publish;

// `PackagePublishOutcome` gained `deferred_to: Option<PublishDeferral>`, and
// `PackagePublishSummary` gained `deferred` and `out_of_scope` counts.
fn finished(status: PackagePublishStatus) -> bool {
    match status {
        PackagePublishStatus::DeferredToTag | PackagePublishStatus::SkippedOutOfScope => false,
        _ => true,
    }
}
```

`pub_dev_trusted_publishing_ref_error` is removed. To plan a run the way `monochange publish packages` does, collect the release's tags in a `PublishReleaseTags` (from the release record's targets, or `configured_release_tags(&configuration, &requests)` without a record), then call `assign_publish_run_scopes(&mut requests, &release_tags, &env)`. `plan_publish_run_scopes(&requests, &release_tags, &env)` returns the same scopes without storing them. Each `PublishRunScope` is `Publish`, `DeferredToTag { deferral, message }`, `OutOfScope { message }`, or `MissingReleaseTag`.
