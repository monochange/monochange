# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Product Purpose

monochange plans monorepo releases from changesets across Cargo, npm, Dart, Python, Go, and Deno. The website introduces the toolkit, links to the monochange book, and provides GitHub sign-in and repository management.

## Users

Inferred from the existing toolkit and documentation: developers maintaining several packages who need to understand which versions and release notes will change before shipping.

## Constraints & Commitments

- The name is always lowercase: monochange.
- Keep the selected flowing three-part mark and custom wordmark, with the approved violet/indigo colour identity.
- The product is free. Pricing must explicitly say “Hey, this is free” and offer no paid tiers.
- Docs must lead to the published monochange book at https://monochange.github.io/monochange/.
- Explain GitHub App installation in the book. The current public GitHub App URL returns 404; do not present it as an available installation until setup is complete.
- Preserve working GitHub authentication, repository management, light/dark themes, and browser icons.
- Use the existing Rust/Leptos application and DigitalOcean deployment. Do not publish packages or manually trigger docs/release workflows.

## Voice

Plain, welcoming, practical. Show real release-planning mechanics; do not invent usage figures, customer proof, or finished capabilities.
