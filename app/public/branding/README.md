## Design rationale

### 11 — Layered Stack

Five rounded bars stacked vertically, each a different brand color (violet → blue → teal → green), with a white version dot on each layer. The shape represents a monorepo where each layer is a package or ecosystem. The tapering width suggests packages that build on each other — the foundation layer is wide, the top layer is narrow, like a dependency tree. Best for app icons, favatars, or anywhere you need a simple vertical mark.

### 12 — Arrow Convergence

Three arrows pointing inward from three directions — violet from top, blue from bottom-left, green from bottom-right — converging on a single central dot. This represents the core idea of monochange: multiple release streams, packages, or workflows converging into one coordinated release. The three source dots represent input packages; the central dot represents the unified release. Best for documentation, onboarding flows, or explaining what monochange does.

### 13 — Diamond Facets

A diamond shape divided into four triangular facets, each a different brand color. An inner diamond outline and a white center dot add depth. The facets represent the different aspects of release management — changesets, versioning, publishing, and coordination — all forming a single cohesive shape. The diamond metaphor suggests something valuable and precise. Best for marketing materials, feature pages, or as a standalone brand mark.

### 14 — Orbital Rings

Three concentric elliptical rings at different angles, each with colored dots orbiting a central nucleus. The rings represent the ongoing, cyclical nature of release management — packages are always in motion, versions are always evolving. The three ring colors (violet, blue, green) represent different release tracks or ecosystems. The central nucleus is the monochange coordination point. Best for backgrounds, animations, or conveying continuous evolution.

### 15 — Honeycomb Tiles

A honeycomb grid of hexagons in alternating brand colors, representing the modular, tile-like nature of a monorepo. Each hexagon is a package that fits perfectly with its neighbors. The honeycomb pattern suggests efficiency (hexagons tile with no wasted space) and interconnectedness (every package touches its neighbors). Best for feature grids, package dashboards, or conveying modularity.

### 16 — Release Pulse

A heartbeat/pulse line across the center, with peaks and valleys at colored dots. The flat baseline represents stable periods; the peaks represent active releases. The three colors (violet → blue → green) show progression over time. This logo conveys that monochange keeps your release process alive and healthy — it monitors, automates, and maintains the rhythm of your releases. Best for status pages, monitoring dashboards, or CI/CD features.

### 17 — Version Arrows

Three upward arrows in different colors (violet, blue, green), each taller than the last, with version labels (0.x, 1.x, 2.x) beneath. This represents the primary goal of monochange: helping packages move through major versions smoothly. The increasing height suggests growth, progress, and the natural progression from early versions to stable releases. Best for changelog pages, version history, or release documentation.

### 18 — Nested Versions

Five concentric rounded rectangles, each smaller and more opaque than the last, with a version badge at the center. The nesting represents semantic version containment — a major version contains minor versions, which contain patches. Each layer is a different brand color, fading from outer (violet) to inner (blue). The central "v1" badge is the focal point. Best for version documentation, semver explanations, or package detail pages.

### 19 — Wave Interference

Three overlapping sine waves in violet, blue, and green, with amber dots at intersection points. The waves represent different release streams or changesets flowing through a monorepo. Where they intersect (the amber dots), changes merge and coordinate. The interference pattern suggests that monochange orchestrates multiple concurrent processes without collision. Best for technical documentation, API references, or explaining merge behavior.

### 20 — Radial Hub

A central hub node connected to six satellite nodes in a hexagonal ring, each a different brand color. Lines radiate outward from the center; the satellites are connected by an outer ring. This represents monochange as the central coordination point for a distributed system — each satellite is a package, ecosystem, or team, and monochange is the hub that keeps them all in sync. Best for architecture diagrams, integration pages, or multi-ecosystem features.

## Color palette

All logos use the monochange brand gradient:

- **Primary**: `#0c8ee7` (blue)
- **Accent**: `#7c3aed` (violet)
- **Secondary**: `#059669` (green)
- **Warm**: `#f59e0b` (amber)
- **Teal**: `#0891b2`

## Recommendations

- **App icon / favicon**: #13 (Diamond facets) or #20 (Radial hub) — simple, distinctive shapes that work at small sizes
- **Wordmark / header**: #11 (Layered stack) — clean vertical mark that pairs well with text
- **Feature pages**: #12 (Arrow convergence) for release consolidation, #17 (Version arrows) for versioning
- **Backgrounds / decoration**: #14 (Orbital rings) or #19 (Wave interference) — organic shapes that fill space without competing with content
- **Status / monitoring**: #16 (Release pulse) — conveys health and activity
